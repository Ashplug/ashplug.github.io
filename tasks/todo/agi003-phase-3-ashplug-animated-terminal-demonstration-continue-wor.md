# # PHASE 3 — Ashplug Animated Terminal Demonstration

Continue working in:

`~/projects/ashplug/`

The homepage hero and design system have already been implemented.

Your task is to create the second major homepage section: an animated terminal demonstration of Ashplug.

This section must appear immediately after the hero.

## 1. Objective

Visitors should understand how Ashplug works by watching a realistic terminal session.

I do not currently have a product recording.

Create the demonstration using:

- HTML.
- CSS.
- Vanilla JavaScript.

Do not use a video recording as a substitute for the initial implementation.

The architecture must allow a real video to replace the animation later.

## 2. Verify the workflow

Inspect the actual Ashplug source code and documentation.

Select one representative workflow that demonstrates the product's real capabilities.

Use only:

- Actual commands.
- Actual syntax.
- Verified application behavior.
- Accurate output.
- Real terminology.

Never fabricate terminal output or pretend Ashplug supports functionality that it does not.

If necessary, consult the tests and implementation to verify the sequence.

## 3. Terminal visual design

Create a polished terminal window.

Consider:

- macOS-inspired window controls.
- Dark terminal background.
- Refined terminal borders.
- JetBrains Mono typography.
- Accurate spacing.
- Subtle syntax highlighting.
- Muted green accents.
- Clear terminal prompts.
- Readable output.

The terminal should look like a genuine developer application.

Do not make it look like a generic code editor.

## 4. Animation

Implement a realistic sequence:

1. Terminal appears.
2. Prompt becomes visible.
3. Command is typed character by character.
4. Command executes.
5. Verified output appears.
6. The next step is displayed where appropriate.
7. The sequence completes naturally.

Use:

- CSS transitions.
- Vanilla JavaScript.
- Cursor blinking.
- Carefully timed typing.
- Subtle output transitions.

Do not use unnecessary animation libraries.

## 5. Interaction

Include a replay control.

The animation should:

- Start when the section enters the viewport.
- Avoid repeatedly restarting while scrolling.
- Support replay.
- Respect reduced-motion preferences.
- Avoid interfering with page scrolling.
- Work without JavaScript-dependent page rendering.

## 6. Future video replacement

Keep the demonstration component modular.

It should support two presentation modes:

- Animated terminal.
- Real video.

For now, implement the animated terminal only.

Do not show an empty video player.

Do not create fake video controls.

## 7. Responsive behavior

The terminal should be visually impressive on desktop.

On mobile:

- Preserve readable text.
- Avoid horizontal page overflow.
- Keep important output visible.
- Use appropriate terminal sizing.
- Ensure controls remain accessible.

## 8. Completion checkpoint

Verify:

- Commands and output against the source code.
- Animation timing.
- Replay.
- Reduced motion.
- Mobile layout.
- Theme compatibility.
- Browser console.

Stop after completing the terminal demonstration.

Do not implement additional homepage sections yet.

Wait for approval before proceeding to Phase 4.
