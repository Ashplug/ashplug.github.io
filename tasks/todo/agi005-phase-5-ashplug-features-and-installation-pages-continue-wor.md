# # PHASE 5 — Ashplug Features and Installation Pages

Continue working in:

`~/projects/ashplug/`

The homepage is complete and approved.

Build the dedicated Features and Installation pages.

Maintain the existing design system and reusable Eta.js components.

## 1. Features page

Create a dedicated page describing the actual Ashplug functionality.

Base every technical claim on the source code.

Organize features into meaningful categories.

For each feature provide:

- Name.
- Description.
- Practical benefit.
- Real example where appropriate.
- Relevant command or workflow.

Use terminal examples where they improve understanding.

Avoid repetitive feature cards.

Make the page feel like technical product documentation rather than a marketing page.

## 2. Installation page

Inspect the actual installation scripts and README.

Create a complete and accurate installation guide.

Include relevant sections:

- Prerequisites.
- Supported operating systems.
- Supported shells.
- Dependencies.
- Installation.
- Initial configuration.
- AI provider setup where applicable.
- First-time usage.
- Updating.
- Uninstallation if supported.
- Troubleshooting.

Use verified commands only.

Every code block must have a copy button.

Use JetBrains Mono for code and terminal examples.

Make the installation process easy to follow.

## 3. Consistency

Both pages must:

- Reuse the global navigation.
- Reuse the footer.
- Support dark and light themes.
- Use the existing typography.
- Work on mobile.
- Have appropriate page titles and metadata.

## 4. Completion checkpoint

Verify all installation instructions against the actual implementation.

Check all internal links and copy buttons.

Stop after completing both pages.

Wait for approval before proceeding to Phase 6.
