# # PHASE 6 — Build the Ashplug Documentation Website

Continue working in:

`~/projects/ashplug/`

The homepage, Features page, and Installation page are already implemented and approved.

Your task is to create a complete new documentation experience.

Use Eta.js for build-time rendering.

Use maintainable Markdown or structured content files as appropriate.

Do not introduce Astro, React, or another frontend framework.

## 1. Documentation research

Inspect:

- Source code.
- README.
- Configuration.
- Tests.
- Examples.
- Existing documentation.
- Installation scripts.

The existing implementation is the source of truth.

Create documentation that accurately explains how Ashplug works.

## 2. Documentation structure

Determine the appropriate navigation based on actual functionality.

Potential sections include:

- Introduction.
- Getting Started.
- Installation.
- Configuration.
- Commands.
- Features.
- Usage Examples.
- AI provider configuration.
- Troubleshooting.
- Contributing.

Only include relevant sections.

Do not create empty placeholder articles.

## 3. Documentation layout

Create a professional documentation interface.

Include:

- Global navigation.
- Documentation sidebar.
- Main content area.
- Breadcrumbs.
- Previous and next article links.
- Responsive mobile sidebar.
- Code blocks.
- Copy buttons.
- Search if it can be implemented reliably.

Use an appropriate readable content width.

Do not let the sidebar consume too much screen space.

## 4. Styling

Use the existing design system.

Use:

- JetBrains Mono typography.
- Dark and light themes.
- Consistent borders.
- Carefully styled code blocks.
- Readable text hierarchy.
- Accessible focus states.

Documentation should feel like a natural extension of the Ashplug website.

## 5. Content quality

Do not blindly copy the README.

Improve organization, clarity, and usability.

Every command must be verified.

Every technical explanation must match the implementation.

## 6. Completion checkpoint

Verify:

- All documentation pages.
- Sidebar navigation.
- Internal links.
- Code copying.
- Responsive behavior.
- Theme switching.
- Generated static output.

Stop after completing documentation.

Wait for approval before proceeding to Phase 7.
